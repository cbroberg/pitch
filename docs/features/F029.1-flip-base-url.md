# F029.1 — Flip adressen til pitch.broberg.ai og gør hjælpesiden domæne-uafhængig

> Forlæder: [F029](F029-broberg-ai-primary-domain.md). Ejerens ordre, 11. september 2026 (dansk tid): *"Flip it - pitch.broberg.ai"*.

## Hvad der ændrer sig

### 1. Adressen appen skriver om sig selv

```
fly secrets set BASE_URL="https://pitch.broberg.ai" -a pitch-vault
```

`BASE_URL` læses ni steder i koden — delelinks (`api/v1/pitches/[id]/share`, `api/cli/push`), alle fire invitationsmails, og de tre mailskabeloner. Alle følger automatisk med; der er ingen anden kilde til adressen i de stier.

**Hvad den IKKE gør:** den ændrer ikke hvad appen svarer på. Fly-proxyen ruter begge værtsnavne til den samme maskine, uafhængigt af denne værdi. Derfor kan et udsendt link ikke gå i stykker af flippet — det er hele grunden til at der ikke skal laves en omdirigering.

### 2. Hjælpesiden holdt op med at nævne et fast domæne

`app/(app)/help/page.tsx` viste `https://pitch.broberg.dk/view/[token]` som eksempel på et modtager-link. Det var det ENESTE sted i app-koden hvor domænet stod skrevet i hånden.

Den oplagte rettelse — skriv `.ai` i stedet — er den samme fejl med en ny dato. I stedet læser siden nu værtsnavnet af selve forespørgslen med `getRequestOrigin()` (den funktion adgangsnøglerne allerede bruger til præcis dette spørgsmål), og teksten indeholder pladsholderen `{origin}`:

```tsx
const origin = getRequestOrigin(await headers());
…
{step.code.replace('{origin}', origin)}
```

Åbner man hjælpen på `.dk` står der `.dk`; på `.ai` står der `.ai`. Eksemplet kan ikke blive forældet igen.

**Sideeffekt, noteret så den ikke overrasker:** at læse forespørgslens headers gør siden dynamisk i stedet for forudbygget. Uden det ville `process.env.BASE_URL` være blevet indbagt på bygge-tidspunktet, hvor hemmeligheden slet ikke findes — og siden ville have vist `http://localhost:3000` i produktion. Det er værre end det hardkodede domæne, og det er derfor løsningen læser headers og ikke env.

### 3. De globale API-noter

`~/.claude/CLAUDE.md` (Pitch Vault API-sektionen) pegede på `.dk` for både læse- og skrive-endpoints. Rettet til `.ai`, så den næste session i et hvilket som helst repo ikke genindfører det gamle domæne. Begge svarer stadig, så intet eksisterende script går i stykker af rettelsen.

## Hvad der bevidst IKKE blev rørt

- **Plan-docs og historik** (`docs/features/F001`, `F011`, `F019.5`, `F027`, `memory/MEMORY.md`) nævner `pitch.broberg.dk`. De beskriver hvad der skete dengang og skal blive ved med at gøre det. At omskrive historik for at matche nutiden gør den usand.
- **Kommentaren i `lib/auth/webauthn.ts`** bruger `.dk` som eksempel på et origin. Det er stadig et gyldigt origin.
- **Ingen redirect.** Se F029's non-goals.

## Verifikation

| Hvad | Hvordan |
|---|---|
| BASE_URL er sat | `fly secrets list -a pitch-vault` → deployed |
| Gamle links lever | samme viewer-token hentet på begge værtsnavne, størrelse + indhold sammenlignet |
| Nye links er `.ai` | del-endpointet kaldt efter flippet, svaret aflæst |
| Hjælpesiden følger domænet | Lens på begge domæner, eksempel-linjen aflæst |
| Intet gået i stykker | `tsc --noEmit` + `vitest run` |
